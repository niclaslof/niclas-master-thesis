# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

This is a two-part monorepo for a KTH master's thesis:

- `thesis/` — LaTeX sources. Entry point `thesis/main.tex` `\input`s each `chapters/NN-*.tex` in order. Bibliography lives in `thesis/references.bib` (`natbib` + `plainnat` style).
- `site/` — Next.js 16 research portal deployed to Vercel.
- `.github/workflows/build-thesis.yml` — CI that compiles the thesis and publishes the PDF.

## Thesis build pipeline (do not bypass)

The LaTeX PDF at `site/public/thesis.pdf` is **generated by CI, not committed by hand**. The workflow triggers only on pushes to `main` that touch `thesis/**`:

1. `xu-cheng/latex-action@v3` runs `latexmk` on `thesis/main.tex` (pdfLaTeX, not xelatex).
2. The resulting `thesis/main.pdf` is copied to `site/public/thesis.pdf`.
3. The bot commits that PDF back to `main` with message `chore: update compiled thesis PDF`.

Implications:
- Editing `.tex` files is the correct way to change the PDF. Do not hand-edit or commit `site/public/thesis.pdf`; CI will overwrite it.
- Local LaTeX compilation is not required and artifacts (`*.aux`, `*.bbl`, `*.fdb_latexmk`, `thesis/main.pdf`, etc.) are gitignored — do not commit them.
- Adding a chapter means creating `thesis/chapters/NN-name.tex` **and** adding an `\input{chapters/NN-name}` line to `thesis/main.tex` in the right position.

## Site (Next.js) commands

All commands run from `site/`:

```bash
npm install
npm run dev      # next dev — local server on :3000
npm run build    # next build
npm run lint     # eslint (flat config in eslint.config.mjs)
```

There is no test suite. There is no typecheck script; rely on `next build` or the editor's TS server (`tsconfig.json` has `strict: true`, `noEmit: true`).

## Site architecture

- **Next.js 16 + React 19, App Router** under `site/src/app/`. Routes are `/` (`page.tsx`), `/thesis`, `/progress`, `/references`. Root layout wires the `Nav` and footer.
- **Critical convention** (from `site/AGENTS.md`, referenced by `site/CLAUDE.md`): *"This is NOT the Next.js you know. This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices."* Prefer consulting the installed docs over memorised App Router patterns before adding route handlers, data fetching, or server/client boundaries.
- **Tailwind CSS v4** via `@tailwindcss/postcss`. Theme tokens are defined as CSS custom properties in `site/src/app/globals.css` and exposed to Tailwind through `@theme inline`. Use the semantic utilities (`bg-card`, `border-card-border`, `text-muted`, `text-accent`, `bg-success/warning/danger`) rather than raw palette colors so the dark theme stays consistent.
- **Path alias** `@/*` → `src/*` (see `tsconfig.json`).
- **Nav** is a client component (`"use client"`) because it reads `usePathname()`; most pages are server components.
- The `/thesis` page serves the statically committed `public/thesis.pdf` in an `<iframe>` — it depends on the CI pipeline above.

## Content that is duplicated between LaTeX and the site

Some thesis content is hand-mirrored into TSX pages and will drift if only one side is updated:

- `site/src/app/progress/page.tsx` hardcodes a `chapters` array with per-chapter status/notes. Update it when chapter state changes; it is not derived from the `.tex` files.
- `site/src/app/references/page.tsx` hardcodes a short curated list. It is separate from `thesis/references.bib`, which is the source of truth for the compiled bibliography.

## Branch convention

This environment runs on a per-task feature branch (see the branch name in the task prompt). Develop, commit, and push there — never directly to `main`, because `main` pushes trigger the LaTeX build + auto-commit workflow.
